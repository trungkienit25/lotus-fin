# P6 full chatbot integration

This is an executable builder integration, not independent qualification. The existing dirty tree was retained; no commit, push, financial schema, production deployment or shared stack mutation was performed.

## Frozen integration contract

`POST /api/method/lotus_fin.api.copilot_integration_api.dispatch` accepts strict `profile`, an allowlisted `action`, optional `action_name`, and a bounded typed operation payload. Actions are `l4_propose`, `l4_confirm`, `l4_cancel`, `l4_status`, `l4_reconcile`, `l5_review`, and `past_final_due`. Actor, roles, site and session binding come from Frappe. Client actor/company/adapter fields are rejected. CORE always returns 503 NOT_AVAILABLE with no fictional records. DEMO additionally requires the server boolean `lotus_copilot_demo_enabled`.

The page and drawer use the same VercelChatPanel, session store, capability toolbar, deterministic router and review views. Requests select a view; text confirmation does not execute. L2 explicitly opens a selected search result and offers an L3 reminder handoff. Reviewed L3 text can be transferred by a separate button into an editable L4 form. No financial facts are fabricated in that draft. A separate proposal button and confirmation button are required.

## Module ownership and compatibility corrections

P6-0 sessionBootstrap/sessionScope and page/drawer bindings were retained. P1/P2 invoice controllers, decoders, transport, HMAC references and L3 lifecycle remain active. L4 and V1 backend modules and L5 policy catalog were reused from current files; `git worktree list` exposed only this checkout, not isolated module worktrees. No unknown external workspace was silently imported. Input module hashes are in `docs/reviews/evidence/p6-full-integration/MODULE_INPUT_HASHES.json`; final source/test hashes are generated by the acceptance runner.

The L4 handoff's class-method HTTP path was not a registered Frappe endpoint. Integration supplies one real dispatch endpoint and registers it in the existing persisted-auth/CSRF runtime allowlist. The module's in-memory ledger did not prove process durability; simulation state and audit are now serialized in one SQLite transaction in the owned site's private directory. This is a fictional receipt store, not a second business ledger. L4's canonical argument digest and challenge checks remain in its service. Internal session bindings are redacted from HTTP DTOs.

L5's standalone simulator is not exposed as an execution API. The integrated route evaluates its server policy catalog and displays explicit denial or unavailable approval-provider status. Its approval/execute routes stay absent. V1's snake_case backend DTO is mapped explicitly into the existing camelCase view. V1 uses the actual deterministic evaluator over fixed October 13 fictional observations; it does not invent native selection handles.

## Quality gates and limits

The unused CORE Company probe was removed. The mobile scenario selector already had the P6-0 responsive correction and is retained for actual browser inspection. CI now has executable integration, TypeScript/build/lint gates; the old echo placeholder and SAST continue-on-error were removed. Four previously dirty files received only whitespace/line-ending normalization; `git diff --check` now succeeds.

Full host pytest collection is not the offline contract gate: three suites require a Frappe environment, while `test_architecture_remediation.py` imports an absent BaselineSourceError and expects legacy contracts absent from the current AI004 implementation. That mismatch is unresolved, retained and reported; no assertions were deleted, weakened or hidden behind xfail. The scoped integration suite selects runnable contracts explicitly. Dependency advisories and graph completeness also remain release gates until qualified.
