## Exact remaining blockers

These are inherited from 86208f4, not newly introduced structural-refactor regressions. The [AI003 final decision package](../features/AI003/AI003_FINAL_PREBUILD_DECISION_PACKAGE.md) explicitly records that reference as NOT READY with PB-SEC-01/PB-DATA-01/PB-DATA-02. Restoring that reference cannot establish scaffold readiness. [Fresh live comparison](evidence/remediation-d8dd7c8-2026-10-01/live-differential.json) confirms all 51 case verdicts are identical at reference and target.

1. **PB-SEC-01 — HIGH: authoritative report revoke is not enforced by the resource guard/cache path.** Existing `Accounts User` fixture initially obtains a forecast/cache entry. Within the transaction, install Custom Role restricting Accounts Receivable to Accounts Manager. `Report.is_permitted()` denies the user and direct ERPNext report execution is denied; `check_ai002_report_permission` still allows. Cached `get_cash_forecast` returns FORECAST_UNAVAILABLE **with opening cash and 10 obligations**, rather than FORBIDDEN/no payload/eviction. Fresh call returns SOURCE_ERROR instead of FORBIDDEN; explicitly checking that user from an Administrator session also allows. Affected: `lotus_fin/lotus_fin/security/access.py:check_report_permission` and `modules/f002_cashflow/service.py:_reauthorize_cached_resources`. Minimal remediation: use the authoritative report permission semantics for the checked user, preserve generic typed denial, and verify cache eviction/no financial payload with real revoke/regrant inside TTL. Green mocked permission tests do not establish this behavior.
2. **PB-DATA-01: missing/malformed overdue basis is treated as usable financial data.** Alter the selected positive AR source row in memory to remove due_date/overdue fields, or provide an invalid due_date without a valid explicit overdue amount. Target returns total AR 565,000, overdue -10,000 and ratio -0.0177 instead of unavailable/typed source failure. Affected: `core/domain/calculators/ar_extractor.py:parse_ar_data`. Minimal remediation: require a valid due-date or explicit overdue basis; preserve available total AR independently when approved, and never fabricate a verified overdue ratio from unknown basis.
3. **PB-DATA-02: duplicate/conflicting observations double-count.** Append an exact copy of a positive source row, or another observation with the same identity and conflicting amount. AR rises 565,000 → 640,000; AP rises 2,765,000 → 2,840,000. AI002 obligation counts rise 3→4 (AR), 7→8 (AP), including conflicting-amount probes. Affected: core AR/AP extractors and `modules/f002_cashflow/adapters.py:_collect_obligations`. Minimal remediation: enforce approved observation identity and reject/deduplicate exact duplicates and reject conflicts; preserve legitimate payment-term/account allocations with explicit tests. These in-memory row mutations were labelled LIVE_ROWS_MUTATION; no invoice/voucher data was written.

Antigravity must remediate these three existing foundation blockers, then Work must independently repeat the focused live cases. No architecture redesign or AI004/AI005 work is required in this task.
