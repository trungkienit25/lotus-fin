# LAYERED ARCHITECTURE (CLEAN / HEXAGONAL ARCHITECTURE)

---

## 1. The Dependency Rule

In the architecture of Lotus Fin, dependencies point strictly inwards:

```text
  +-------------------------------------------------------------+
  | 1. PRESENTATION LAYER (Web / Frappe Entrypoints, DTOs)      |
  |   │                                                         |
  |   ▼                                                         |
  | 2. APPLICATION LAYER (Use Cases, Agent Runner, Ports)       |
  |   │                                                         |
  |   ▼                                                         |
  | 3. DOMAIN LAYER (Entities, Domain Policies, Contracts)      |
  |   ▲                                                         |
  |   │                                                         |
  | 4. INFRASTRUCTURE LAYER (LLM Adapters, DB, ERP Gateways)   |
  +-------------------------------------------------------------+
```

- **Domain Layer** is the core domain model: **Zero** dependencies on third-party libraries, Frappe framework, or database drivers.
- **Application Layer** depends solely on abstractions (Interfaces / Ports) defined by the Domain or Application layer, never instantiating concrete adapters directly (Inversion of Control).
- **Infrastructure Layer** implements these Ports and injects concrete adapters into the Application at runtime.
- **Presentation Layer** receives inbound user/web requests, normalizes payloads into validated DTOs, and invokes Application Services.

---

## 2. Layer Responsibilities

### 2.1. Presentation Layer (`lotus_fin/presentation`)
- **Responsibilities**:
  - Serves as the inbound system boundary interacting with external callers (Frappe Web Desk, REST APIs, React Frontend UI).
  - Accepts HTTP requests, parses raw payloads into strongly-typed Data Transfer Objects (DTOs) with Pydantic runtime validation.
  - Establishes the authenticated user security context (`UserPrincipal`) from active sessions (`frappe.session`).
- **Core Components**:
  - `controller/copilot_controller.py`: Receives chat queries or dispatches financial actions.
  - `dto/chat_request.py`: `SendMessageDTO`, `ContextFilterDTO` (input validation contracts).
  - `dto/chat_response.py`: `ChatResponseDTO`, `ToolTraceDTO`, `UIWidgetDTO` (normalized response payload contracts).

---

### 2.2. Application Layer (`lotus_fin/application`)
- **Responsibilities**:
  - Orchestrates business workflows. Contains no hardcoded math equations; coordinates end-to-end execution of use cases.
  - Manages the ReAct Agent Loop: constructs system prompts, feeds queries and tool registries to the LLM, handles tool execution requests, invokes tool invokers, and synthesizes grounded answers.
  - Declares abstract outbound contracts (Ports) adhering to the Dependency Inversion Principle.
- **Core Components**:
  - `service/copilot_service.py`: Implements `IChatService`, orchestrates chat sessions, and interfaces with `AgentRunner`.
  - `agent/agent_runner.py`: Guarded ReAct execution loop with a strict hard ceiling (`max_iterations = 4`) preventing runaway loops.
  - `agent/prompt_engine.py`: Assembles grounding rules, company security boundaries, and LLM behavior guidelines.
  - `port/i_chat_service.py`: Chat Service abstraction interface.
  - `port/i_llm_provider.py`: LLM abstraction declaring `generate(messages, tools) -> LLMResponse`.
  - `port/i_tool_registry.py`: Interface for registering, resolving, and filtering callable tools.

---

### 2.3. Domain Layer (`lotus_fin/domain`)
- **Responsibilities**:
  - Business heart of the platform. Encapsulates Entities, Value Objects, and core Schemas.
  - Fully decoupled from the Frappe framework, external databases, or cloud vendors.
- **Core Components**:
  - `model/chat_session.py`: Manages session state, conversation history, and execution audit trails (`ToolTrace`).
  - `model/user_context.py`: `UserPrincipal` value object representing authenticated identities, company affiliations, RBAC role sets, and financial closing dates.
  - `policy/permission_policy.py`: Declares `IPermissionPolicy` interface and `ModuleSecurityPolicy` (Open-Closed Principle).
  - `schema/tool_definition.py`: Declares tool specifications as OpenAPI-compliant JSON Schemas.
  - `schema/tool_call_request.py`: Strongly typed payloads for tool call requests generated by the LLM.
  - `schema/tool_execution_result.py`: Deterministic execution result DTO bundling UI widget payloads.
  - `repository/i_session_repository.py`: Repository interface for persisting and retrieving chat sessions.

---

### 2.4. Infrastructure Layer (`lotus_fin/infrastructure`)
- **Responsibilities**:
  - Implements all outbound ports and technical adapters.
  - Handles real I/O operations: HTTP requests to LLM providers, database queries to Frappe/ERPNext, in-memory caching, and observability logs.
- **Core Components**:
  - `llm/adapter/`: Concrete adapters (`OpenAILLMAdapter`, `GeminiLLMAdapter`, `MockLLMAdapter`) implementing `ILLMProvider`.
  - `llm/llm_factory.py`: `LLMProviderFactory` dynamically loading provider credentials and initializing runtime adapters.
  - `security/frappe_access_gateway.py`: Implements `IPermissionPolicy`, validating DocType and Report permissions against ERPNext.
  - `erpnext/erpnext_gateway.py`: Extracts operational data from General Ledger, AR, AP, and Invoices.
  - `observability/observability.py`: Audit logging with automatic PII sanitization and correlation ID propagation.
  - `persistence/in_memory_session_repository.py`: In-memory thread-safe chat session repository.
  - `tool/command/` & `tool/invoker/`: Command pattern encapsulation converting calculation engines into secure, callable tools.

---

### 2.5. Modules Layer (`lotus_fin/modules`)
- **Responsibilities**:
  - Dedicated deterministic financial calculation engines (F001 through F007).
  - Operate hermetically with strict numeric contracts; never infer or hallucinate figures; verified across extensive test suites.
