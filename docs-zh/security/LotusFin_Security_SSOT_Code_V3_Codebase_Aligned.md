# 1. 规范化关键词定义

- `MUST` / `MUST NOT` (必须 / 严禁): 系统 MVP 阶段已启用功能的强制性要求。
- `SHOULD` / `SHOULD NOT` (应当 / 不应当): 推荐性安全实践；任何偏离必须在架构评审中提供书面理由。
- `MAY` (可以): 可选实现项。
- 仅当某项功能在代码层面完全不存在可达调用路径时，对应安全条款方可标记为 `N/A`。

# 3. 系统底层架构假设

```text
ERPNext / Frappe 底层框架
  ├── 核心 DocTypes 数据模型
  ├── Query 报表引擎
  ├── 身份认证与权限校验框架
  └── 会计凭据与总账流水
        ↓
Lotus Frappe 自定义扩展应用
  ├── @frappe.whitelist() 安全暴露端点
  ├── 报表数据提取与校验适配器
  ├── 系统 Hooks 与定时调度器
  └── 确定性金融智能计算核心服务 (F001–F007)
        ↓
强类型金融工具集合 (Command Pattern)
        ↓
财务 Copilot 智能体 (ReAct Agent)
```

**核心红线：** 系统严禁引入第二个独立的可写会计总账。所有账务记录必须完全以 ERPNext 原生 General Ledger 为唯一事实源。

# 4. 强制性核心安全不变量 (Mandatory Invariants)

- `INV-01` **鉴权决策归属不变量：** 访问授权决策必须且只能由服务端代码结合 Frappe 底层权限框架做出，严禁由大语言模型判定。
- `INV-02` **多租户数据隔离不变量：** 每一个业务数据查询请求必须强制限定在调用者已被明确授权的企业公司 (`company`) 范围之内。
- `INV-03` **财务数值计算不变量：** 实质性财务数据指标必须全部来自确定性算法引擎与经过核验的正式单据，严禁大模型参与数值推算。
- `INV-04` **缺失数据显式表达不变量：** 当数据源发生错误或凭证缺失时，严禁静默将其转化为 `0`，必须显式抛出 `UNAVAILABLE` 或明确异常。
- `INV-05` **现金流口径严谨不变量：** 严禁将简单的 `应收余额 - 应付余额` 伪称为未来现金流预测。
- `INV-06` **凭据最小特权不变量：** AI 智能体严禁持有底层数据库直连凭据或银行资金账户直联密钥。
- `INV-07` **高危银企直联阻断：** MVP 阶段对涉及资金划拨的银行直联写接口一律实施硬阻断 (`R4=DENY, R5=DENY`)。
- `INV-08` **输入与输出全量不可信：** 外部输入文本、报表字段、供应商名称以及大模型生成内容，在呈现层均视作不可信数据，必须执行 HTML 实体清洗与 XSS 过滤。
