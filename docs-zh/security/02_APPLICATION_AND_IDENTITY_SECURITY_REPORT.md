## 2. 应用安全控制要点与实现蓝图

### 2.1. 会话状态强校验与防 CSRF 跨站请求伪造

#### 痛点场景
跨站请求伪造 (CSRF) 漏洞可能使恶意第三方站点利用受害者当前已登录的浏览器会话，在用户毫不知情的情况下诱发越权财务操作（如私自录入记账凭单或指派催收任务）。此外，若系统仅依赖内存缓存判断会话有效性，已被后台禁用的账户在缓存过期前仍能非法操作。

#### 解决方案与技术蓝图
1. **数据库直查账号激活状态：** 在每个 API 请求入口拦截时，直接向底层数据库查询确认用户账号状态 (`enabled = 1`)，跳过易失性内存缓存。
2. **常数时间防 CSRF 令牌匹配：** 针对所有破坏幂等性的数据变更请求 (POST, PUT, DELETE)，强制要求请求头包含有效的 `X-Frappe-CSRF-Token`。令牌校验严格采用 Python `hmac.compare_digest` 常数时间比对算法，杜绝侧信道时序攻击。

### 2.2. 基于角色的访问控制 (RBAC) 与多租户 IDOR 越权拦截

#### 痛点场景
不安全的直接对象引用 (IDOR / BOLA) 常发生在多租户 SaaS 系统中。当攻击者故意篡改请求体中的公司参数（例如将 `company="本公司"` 篡改为 `company="友商竞争对手"`），若后端缺乏鉴权，将直接导致机密资产负债表与发票数据外泄。

#### 解决方案
1. **参数零信任原则：** 客户端请求附带的企业标识符 (`company`) 均视为不可信数据。系统全部通过底层用户权限表 (`tabUser Permission`) 重新鉴权。
2. **Fail-Closed 访问阻断：** 任何未授权的企业数据查询均直接抛出 `CompanyAccessError`，立即终止后续查询执行。
3. **模块级 RBAC 矩阵：**

| 模块代号 | 金融服务 / 业务能力 | 最低准入角色权限 | 权限控制机制与拦截点 |
| :--- | :--- | :--- | :--- |
| **F001** | 企业财务健康分析仪表盘 | `Accounts User`, `Accounts Manager` | 访问网关公司级读权限强校验 |
| **F002** | 30 天每日现金流预测推演 | `Accounts Manager`, `Auditor` | 报表白名单强校验 (`check_ai002_report_permission`) |
| **F003** | 往来账龄与风险信号监控 | `Accounts User`, `Accounts Manager` | 安全注册表白名单 (`MODULE_SECURITY_REGISTRY["f003"]`) |
| **F004** | 多变量 What-If 财务压力模拟 | `Accounts Manager`, `System Manager` | 压力测试情景引擎租户隔离策略 |
| **F005** | 中小企业商业信贷产品撮合 | `Accounts User`, `Bank Officer` | 商业金融准入规则与画像脱敏过滤 |
| **F006** | 贷款分期与利率冲击模拟 | `Accounts User`, `Accounts Manager` | 纯数学精算域计算器校验 |
| **F007** | 客户账单催收协助与对账函生成 | `Accounts User`, `Accounts Manager` | 销售发票上下文访问权限核验 |
| **L4** | 核心业务凭据生成与外部发函 | `Accounts Manager`, `System Manager` | Level 4 人机协同双阶段确认交互卡片 |
| **L5** | 自主修改会计总账 / 自动对外转账 | **彻底禁止调用 (ALL DENIED)** | Fail-closed 默认阻断 (`CAPABILITY_DISABLED`) |

### 2.3. 不透明 HMAC 单据引用令牌 (`InvoiceReferenceV2Codec`)

#### 痛点场景
如果直接在 API 报文和前端 URL 中暴露自增序列号或有规律的账单主键（如 `ACC-SINV-2026-00001`），攻击者可通过编写爬虫递增数字，对系统内所有企业的发票发起遍历爬取。

#### 解决方案
Lotus Fin 采用 **HMAC 不透明签名单据引用令牌** 代替明文主键传递给前端，每个令牌基于 `HMAC-SHA-256` 签名并与当前用户的会话上下文强行绑定：

```text
通信报文编码格式:
ref.v2.<Base64Url(声明载荷 Claims)>.<Base64Url(HMAC 签名)>
```

*已签名声明载荷包含的核心字段：*
* **协议版本:** 不透明操作者标准版本 (`opaque-actor.v1`)。
* **业务用途:** 明确限定操作类型（如 `invoice.open`、`invoice.cursor`）。
* **密码学单向哈希:** 操作者账号 ID 与当前会话 ID 的不可逆 HMAC 摘要 (`aref_...`, `sref_...`)。
* **租户空间范围:** 站点唯一标识、所属企业 ID 及数据版本号。
* **数据版本与乐观锁:** 对应单据主键及并发修改版本号 (`record_version`)。
* **时间生命周期:** 签发时间 (`issued_at`) 与严格的过期时间 (`expires_at`)。

*校验与防护实效：*
* 令牌强制限定 **300 秒生存时间 (TTL)**。
* 令牌与当前会话绑定，攻击者即使窃取令牌并在自身浏览器会话中使用，将因会话哈希不匹配立即被识别为 `Scope mismatch` 予以阻断。
* 包含乐观锁版本号，若发票在期间已被修改，比对立即报 `Stale read` 阻止读取脏数据。

### 2.4. 查询计算资源硬性约束与防拒绝服务限制 (DoS Guardrails)

为防止恶意客户端或异常并发请求超大跨度的财务数据（例如一次性抓取跨度 10 年的总账凭证或请求 50,000 条明细）导致 MariaDB 内存爆满和线程池耗尽，系统在数据读取适配器中落地了硬性配额：

| 资源 / 参数维度 | 默认安全值 | 硬性最高上限 | 超限处理逻辑 |
| :--- | :--- | :--- | :--- |
| **分页大小 (Page Size)** | 20 条 | **50 条** | 超过 50 条直接阻断并返回参数校验错误 |
| **查询时间跨度** | 90 天 | **365 天** | 当 `end_date - start_date > 365` 时拒绝执行 |
| **未来时间策略** | 当前自然日 | 严禁跨入未来 | 当 `posting_date > Today` 时拒绝入账查询 |
| **游标分页遍历深度** | 1 页 | **连续 5 页** | 触发配额后强制标记 `incomplete_coverage = true` 并终止 |
| **单次查询关联单据数** | 20 张 | **51 次检查** | 达到阈值立即退出循环，防止 CPU 耗尽 |
| **单次详情精准解析** | 1 条 | **1 条** | 严格限制为选中的唯一目标凭证 |
| **供应商数据体上限** | - | **256 KiB** | 数据体超标立即掐断上游连接 |
| **统一响应信封上限** | - | **64 KiB** | 确保前端传输轻量化与极速渲染 |
| **数据库查询执行超时** | 3.0 秒 | **5.0 秒** | 超过 5 秒直接中断套接字连接 |
