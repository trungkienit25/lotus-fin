## 2. 纵深防御安全分析：从云边界到应用运行时

系统网络拓扑落地了严密的**四层纵深防御体系 (Four-Tier Defense-in-Depth)**，覆盖第 3 层（网络路由）、第 4 层（传输层状态包过滤）以及第 7 层（应用网关代理与 TLS 终结）。

### 2.1. 云环境边界安全：VPC、Internet 网关与安全组

#### 1. VPC 私有隔离与互联网网关 (IGW) 彻底解耦
* **架构蓝图：** 虚拟机实例部署在专用私有 VPC 子网中，拥有独立的私网网段 (`10.0.0.0/16`)。虚拟机物理网卡仅持有内网 IP 地址 (`10.0.1.5`)。
* **防护实效：** 主机网卡完全脱离公网广播域。外部网络通信统一由 VPC 互联网网关 (IGW) 通过 1:1 弹性公网 IP (Elastic IP) NAT 转换完成。彻底阻断 Layer 2 ARP 欺骗攻击、广播风暴及云上相邻租户旁路嗅探。

#### 2. 云安全组 (Stateful L4 状态防火墙)
* **入站严密收敛 (Zero-Trust Ingress)：**
  * `TCP 22 (SSH):` 仅供系统管理运维使用。生产环境严格限制在固定的管理员公网 IP 白名单 CIDR 段内，杜绝全网 SSH 暴力破解扫描。
  * `TCP 80 (HTTP):` 仅用于 Let's Encrypt ACME HTTP-01 自动化证书签发校验，并配置即时 `HTTP 301` 强制跳转至 HTTPS。
  * `TCP 443 (HTTPS):` 接收公网 Web 与 API 请求的唯一合法加密业务通道。
  * **默认丢弃全部非白名单入站流量：** 包含 MariaDB `3306`、Redis `6379`、Gunicorn `8000` 以及 Docker `8080` 在内的所有其他端口，**在云虚拟化边界被直接丢弃 (DROP)**，完全不消耗宿主机的 CPU 算力与网卡带宽。
* **出站策略 (Egress)：**
  * `全量放行 (0.0.0.0/0 ALLOW):` 保证系统能够正常下载 Linux 内核安全补丁、拉取 Docker 官方镜像及向大模型供应商 (Google Gemini / OpenAI) 发送加密 API 请求。
  * **有状态连接跟踪保障 (Stateful)：** 云安全组具备有状态特性，入站请求建立握手后，响应报文自动追踪放行；出站放行并不意味着开放任何外部入站端口。

### 2.2. 宿主机本地防火墙 (UFW — 内部第二防线)

#### 痛点场景
若云管理控制台发生人为误操作（例如运维误将安全组设为 `0.0.0.0/0` 全通），虚拟机将直接暴露于公网端口扫描之下。

#### 解决方案与防护效果
Lotus Fin 在宿主机 Linux 系统层面开启独立软件防火墙 (`UFW`):
* **独立防御基线：** UFW 直接在 Linux 内核层 (`netfilter/iptables`) 执行过滤，不受云厂商配置漂移影响。
* **双重白名单机制：** UFW 保持默认入站全拒绝策略，仅放行 22、80 和 443 端口。即使外部云安全组失效，内部防火墙依然能精确截断针对内部未授权端口的探测。

---

### 2.3. L7 反向代理网关：Nginx 与网络层的职责边界

#### 职责划分与能力对比
必须严格区分 **L4 传输层过滤** (由云安全组与 UFW 承担) 与 **L7 应用层代理** (由 Host Nginx 承担) 的技术边界：

| 架构分层 | 核心组件 | 安全职责范畴与实施标准 |
| :--- | :--- | :--- |
| **L3 / L4 (网络与传输层)** | **云安全组 & 宿主机 UFW** | • 在创建 Socket 连接前直接丢弃非法 IP 数据包。<br>• 仅放行 22、80、443 TCP 端口。<br>• 防御 SYN Flood、UDP 洪水及全网端口盲扫。<br>• 内核层高速运行，零应用内存开销。 |
| **L7 (应用与安全传输层)** | **Host Nginx 反向代理** | • **SSL/TLS 加密终结:** 卸载密码学运算开销，强制启用 TLS 1.3 与前向保密套件。<br>• **防 DDoS 与暴力破解:** 基于 `limit_req_zone` 限制单 IP 频次 (10 req/s, 突发容忍 20)。<br>• **请求体体积强约束:** 检查 `Content-Length`，对大于 50MB 的非法语料上传在入口阻断。<br>• **安全响应头强力注入:** 注入 HSTS、严格 CSP、nosniff 及防点击劫持头。<br>• **同源请求安全调度:** 本地高速分发 React SPA 静态包 (延迟 <10ms)，安全代理 API 流量至回环端口。 |

### 2.4. 宿主机内部容器微隔离 (Docker Bridge 隔离)

#### 痛点场景
若将带有持久化存储的有状态组件（MariaDB 3306 端口、Redis 6379 端口）或后端 WSGI 服务 (Gunicorn 8000 端口) 暴露给外部网络，攻击者可通过数据库爆破、未授权访问漏洞或远程内存溢出直接破坏财务账目。

#### 解决方案
1. **本地回环网关绑定 (Loopback Binding):** 容器微服务入口 (`frappe_docker-frontend-1`) 仅绑定到宿主机本地回环接口 `127.0.0.1:8080`，拒绝任何来自非本地网卡的连接。
2. **私有 Docker 桥接网桥 (Bridge Network):** MariaDB 数据库 (`db`) 与 Redis 消息队列/缓存 (`redis-queue`, `redis-cache`) **完全不配置宿主机端口映射**。全部通信被严密封闭在不可路由的 Docker 私有桥接网络内。
3. **容器非 root 权限降权执行:** 容器进程运行在无特权的系统服务账号下：业务进程使用 `frappe` (UID 1000)，数据库使用 `mysql` (UID 999)，缓存使用 `redis` (UID 999)。
4. **日志配额与虚拟内存保护:** 容器日志强制限制单文件最大 10MB，最多保留 3 份历史轮转归档（单容器总日志 $\le 30 \text{ MB}$），并配置 2.0 GiB Swap 空间 (`swappiness = 10`) 彻底预防数据库进程因内存突增被 OOM Killer 强杀。

#### 验证证据
通过底层网络套接字审查 (`ss -tulpn`) 验证宿主机监听状态：
* 公网监听 (`0.0.0.0`): 仅有 Host Nginx (80/443 端口) 与 SSH 守护进程 (22 端口)。
* 本地回环监听 (`127.0.0.1`): 仅有 Docker 代理的 8080 端口。
* 3306 (MariaDB) 与 6379 (Redis) 外部公网监听数严格为 **0**。
