# Lotus Fin — 企业级财务安全与权限架构设计规范 (中文版)

本文档阐述了 Lotus Fin 在中小企业财务管理场景下的核心安全架构、数据合规标准及双重控制安全门禁设计原则。

---

## 🛡️ 1. 核心安全哲学与防御纵深

作为直接连接企业真实总账与银行流水的智能化中枢，Lotus Fin 严格遵循**防御纵深（Defense in Depth）**与**最小权限原则（Least Privilege）**：

1. **确定性优先于大模型生成（Deterministic over Generative）：**
   - 严禁大模型自行生成、估算或插值任何财务数字。
   - 所有关键财务指标（如现金流量、应收应付账期、利息测算）均由经过独立单元测试与审计的 Python 定量工具模块计算，大模型仅负责语义解析与呈现结构组织。

2. **零系统代码与内部标记泄漏（Presentation Gate）：**
   - 建立自动化文本清洗网关，在向最终用户呈现或持久化对话历史前，强制过滤底层技术常量（如 `STRICT_BASELINE_V1`、`has_constituent_deficit` 等内部数据库字段和布尔值标记）。

3. **高可用 API 凭证管理与降级机制：**
   - 采用多 Key 动态轮换适配器（Gemini, OpenAI, NVIDIA NIM），杜绝因单一 API Key 超额或限流（429 Too Many Requests）导致企业业务中断。

---

## 🔐 2. 双重授权安全策略门禁 (L5 Dual-Control Policy Gate)

针对涉及总账变动或资金流动的敏感动作，系统在前端及后端均建立了硬性策略门禁：

| 业务动作 | 风险级别 | 门禁处置策略 | 授权审批要求 |
| :--- | :---: | :---: | :--- |
| **提交销售发票 (Submit Sales Invoice)** | High | 校验发票唯一性与借贷平衡 | 需销售会计或财务主管单人确认 |
| **作废销售发票 (Cancel Sales Invoice)** | Critical | 强制拦截自主执行，防范账实不符 | **双人复核控制：** 需财务总监（Controller）与董事会成员双独立签字批准 |
| **发起资金划拨 (Request Disbursement)** | High | 校验采购发票真实性与预算上限 | 应付专员提交申请 -> 财务经理审批预算 |
| **对外转账执行 (Execute Wire Transfer)** | Critical | **绝对阻断（Blocked）** | 严禁 AI 与后台脚本发起自动转账；必须由出纳通过网银及物理 U-Key 人工完成 |
| **自动总账对账 (Autonomous Reconciliation)** | Critical | **绝对阻断（Blocked）** | 严禁自动化调平账实差异；必须保留完整人工调整凭证与审计底稿 |

---

## 📜 3. 合规性设计与标准对齐

- **ISO/IEC 27001 对齐：** 实现了完备的系统日志留存与不可篡改审计追踪（包含请求来源 IP、操作人、会话 ID、时间戳及变更差异）。
- **GDPR 与隐私保护：** 对涉及客户与供应商的个人隐私数据（如联系方式、银行账号）进行脱敏存储与访问隔离。
- **环境隔离标准：** 生产环境与测试环境通过独立 Docker 虚拟子网（`lotus_prod_net`）进行隔离，严禁开发环境直连生产数据库。
