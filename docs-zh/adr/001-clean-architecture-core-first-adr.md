# ADR 001: 整洁架构标准、单文件 200 行上限与杜绝临时脚本

- **状态:** 已采纳 (Accepted)
- **适用范围:** Lotus Fin 核心代码库与相关微服务

---

## 1. 背景与上下文 (Context)
在金融科技与会计核算系统中，非结构化的随意开发往往会引入散落的临时脚本（例如手动数据库修复补丁、硬编码的临时重算逻辑、一次性的对账提取脚本）。这会导致：
- 核心业务逻辑严重碎片化与丢失。
- 缺乏自动化回归测试覆盖，导致底层总账核算反复出现偏差风险。
- 代码库体积极速膨胀，严重挤占人类工程师与 AI 编码代理的上下文窗口。

---

## 2. 决策内容 (Decision)

### 2.1. 核心优先实现 (严禁临时脚本)
- **严格禁止:** 在批准的架构边界之外编写临时运维脚本或未结构化的零散工具目录。
- **整洁架构分层职责分配:**
  1. `Domain Layer (领域层)`: 定义纯业务实体、校验不变量、值对象与全局常量。
  2. `Application / UseCase Layer (应用层)`: 统一协调业务流程、ReAct 智能体循环、事务处理与互斥锁。
  3. `Infrastructure / Delivery Layer (基础设施层)`: 承载具体的数据库访问网关、大模型提供商适配器与 RESTful API 控制器。

### 2.2. 单文件代码量严格上限: < 200 行
- 所有生产代码文件必须严格控制在 **200 行代码以内**。
- 当文件长度接近 200 行时，必须主动重构解耦：
  - 将 UseCase 拆分为：协调器 (Coordinator) + 评估器 (Evaluator) + 查询处理器 (Query Handler)。
  - 将 Controller 拆分为：REST 端点 + DTO 解析器 + 序列化适配器。

### 2.3. 强制性验证验收标准
每一个金融功能用例必须包含：
- **单元测试 (Unit Tests):** 纯内存中的确定性测试，验证核心数学公式与边界情况，零数据库外部依赖。
- **集成测试 (Integration Tests):** 验证完整的请求/响应信封与数据库底层账目的一致性。
