## Material findings

**IND-01 — Required ERP runtime/schema coupling.** Dockerfile starts from ERPNext; judge init uses `--install-app erpnext`. AI001 calls registered ERP reports; AI002 queries GL and uses Account/Company/Party Type/invoices; AI003 consumes that AR foundation and Purchase Invoice schedules. Removing imports cannot solve this. See dependency matrix and authority map.

**IND-02 — Native data/authorization authority missing.** No approved Lotus invoice source or tenant policy backing P1/P2 reads. The smallest next step is an authority decision and adapter, not enabling legacy ERP target discovery. Native context/field policy must be proven against ordinary users.

**IND-03 — Security contracts retain ERP semantics.** AuthorizedReadContext and SourceEvidence accept only ERP_READ/DEMO_ISOLATED; SelectionClaimsV2 fixes `doc_type="Sales Invoice"`; cursors fix `name ASC`. Migrate these under a reviewed versioned contract, keeping all purpose/actor/session/product/site/company/source/version/expiry/query/key bindings. Never relabel legacy references as native.

**IND-04 — Legacy identity fallback is unsuitable.** `copilot_controller.py:56–62` substitutes Administrator/System Manager if identity/framework is absent; `f002_cashflow/service.py:100–109` falls back to Administrator; `frappe_access_gateway.py` has permissive no-framework test behavior. `copilot_api.chat_copilot` is guest-enabled and catches errors into legacy routing. These are source risks, not a demonstrated live exploit. P1 strict authorizer's failure behavior is materially safer and must remain intact.

**IND-05 — Incomplete integration and release identity (FIN-F02).** Public HTTP never reaches the typed services, no port implementation, no approved native target, no production action mount, untracked UI and dirty corrections. Current HEAD check and historical image evidence support FAIL; see reproducibility plan.

**IND-06 — Historical UI/L3 failures need fresh acceptance.** Latest packet reports 18 expanded P2-B Node failures, 8/36 React failures, four L3 controller and four L3 React failures. Preserve FIN-F01/F03–F10 correction oracles. Final verification detected concurrent changes to eight frontend source/test files after this audit's baseline, including action controllers/decoders and L3 controller/view. This audit made no edits to them and did not rerun or certify the historic failures or corrections against their new hashes. Their present acceptance status is UNVERIFIED; do not declare them still reproduced or fixed.
